1. Before you start

1
Docker Desktop is running. The API needs Postgres (host port 5434) and Redis (6379); pnpm bootstrap starts both and pnpm dev checks them.
2
The key is in .env. OPENAI_API_KEY=sk-… at the repository root. With it, the API reports "provider": "openai" at http://localhost:4000/api/health; without it, "mock".
3
Start everything: pnpm dev (or pnpm bootstrap once on a fresh clone, then pnpm dev). Open http://localhost:3000 in Chrome, Edge or Safari 16.4+.
4
Allow the microphone when the browser asks, after clicking the orb the first time. Use headphones or keep the volume moderate: the agent's own voice through speakers can trigger the barge-in detector if echo cancellation struggles.
5
Pick a persona (top right). Alice in Engineering has 11 of 20 PTO days left; Bob in Sales has 7 of 25; Carla in People Operations has 17 of 20. Balance questions and tickets use the selected persona automatically.
The header shows two badges: the connection state (connected once the socket session is ready) and the provider (OPENAI or MOCK). Hover the provider badge for what the mode means.

2. Two modes: OpenAI and mock

OpenAI modeMock mode (no key)
Understands speechYes, real transcriptionNo: replays six demo utterances in order, one per spoken turn
Understands questionsYesKeyword planner: handles the demo phrases, not free-form questions
VoiceNatural speech, streamedA short chime whose length follows the reply
Tools, citations, trace, ticketsAll realAll real (same code), deterministic
Cost≈ $0.005 per spoken turnNothing

Everything in this guide is written for OpenAI mode. In mock mode use the text box for your own questions and expect the voice path to transcribe one of the demo utterances regardless of what you said.

4. Voice flows

4.1 Hands-free (default)

Click the orb once. Say a question and stop talking.
The orb turns green while you speak; ~0.7 s after you stop it turns amber, your words appear on the right, the trace fills, the answer streams in and is spoken. The orb returns to green (still listening) when playback ends.
Ask a second question without touching anything.
It is picked up the same way: hands-free stays on until you click the orb again.
Barge-in: while the agent is speaking, start talking.
Playback stops within a word or two, the trace shows the turn was cancelled, and your new utterance is handled.

4.2 Push to talk

Switch to Push to talk. Press and hold the orb, speak, release.
Only what you said while holding is sent; the label reads "Release to send" while held.

4.3 Text fallback

Type in "Or type a question…" and press Enter.
Same pipeline, same trace, spoken reply.

4.4 Stop and reset

Click Stop during a long answer.
Speech and generation stop; the partial answer is kept.
Click Reset.
Empty transcript, "Say something" placeholder, a new conversation id (the previous one is under Conversations).

5. The six assessment scenarios

Say each phrase (or type it). The "look for" column tells you how to prove the behaviour, not just see an answer.

#ScenarioSayLook for
1Voice conversation"What are the core working hours for remote employees?"Full voice round-trip; STT badge filled; answer cites the Remote Work Policy or Handbook.
2Knowledge-grounded answer"How many vacation days do new employees get, and can I carry unused days over?"Chips [1] [2]…; sources sheet shows PTO and Leave Policy › Allowance and › Carryover; trace shows the pre-fetched search graded strong.
3Semantic retrieval"How long do I have to claim back money I spent on a business trip?"The policy says "submitted within 30 days": no shared words with the question, yet it is found and cited.
4Agentic execution"I'd like to take off from December 21st through the end of the year. How many PTO days would that cost me, and do I have enough left?"Several steps in the trace: pre-fetched search, then search_knowledge_base and get_leave_balance together (and count_business_days / calculate when used). Answer: six PTO days, eleven remaining for Alice.
4bConfirmed action"My laptop screen is cracked, what should I do?" then "Yes please, high priority"First answer quotes the equipment policy and offers to open a ticket; second runs create_support_ticket and reads out a TCK- reference. Open Tools & tickets: the ticket is there, high priority, linked to the conversation.
5Contextual follow-upAfter #2: "And what about sick days?"Answered from the same policy without asking what you mean; the history is in the prompt.
6Insufficient information"What's the policy on bringing dogs to the office?"Trace: pre-fetch graded weak, a second search with new phrasing, then an honest "the knowledge base doesn't cover this" with a pointer to People Operations and an offer to open a ticket. No citations.
Also try the persona switch: select Bob, ask "How much vacation do I have left?" and expect seven of twenty-five days; nobody is ever asked for an employee id.

6. Tool-by-tool checks

ToolSayExpect in the traceWhere the effect is visible
search_knowledge_baseAny policy question, e.g. "Do I need a receipt for a $20 taxi?""Searching the knowledge base" with queries; result "N passages (strong)"; grade badgeCitation chips, sources sheet, Knowledge page search for the same query

get_leave_balance"How many PTO days do I have left?""Looking up leave balance" → "Alice Nguyen: 11 of 20 PTO days left …" (~150 ms simulated HR latency)HR cards on the Tools page show the same numbers

Expand any trace row (chevron) to see the exact arguments the model sent and, for searches, the passages with their scores. Failed tools show a red mark with the error; the agent recovers in the next step.

7. Tools & tickets page

Open Tools & tickets in the sidebar.
Four sections: Support tickets, Tool activity, Tool catalogue (six cards, each with its argument schema and a "Try:" phrase), HR system (three personas with PTO and sick meters). The page refreshes every few seconds.
Create a ticket by voice in another tab, then come back.
The new row appears within ~8 seconds: reference, title, priority badge, requester id, "View conversation" link.
Change a ticket's status from Open to In progress or Resolved.
Toast "TCK-… marked resolved"; the row updates; GET /api/hr/tickets reflects it.
Read the Tool activity bars.
Calls per tool with failure counts and average duration; the recent-invocations table links each result to its conversation.

8. Knowledge base page

Search "What happens to my unused vacation at the end of the year?" in Hybrid mode.
Ranked passages with three score bars (fused, dense, keyword); the PTO policy's Carryover section first.
Switch to Dense and Keyword.
Orderings differ; Keyword shows BM25-only ranks, Dense embedding-only.
Click a document in the left list.
A sheet with the rendered document, its category, chunk count and sections.
Click Reindex all.
The button counts jobs ("Indexing 3/12 …") as the BullMQ worker processes them; a success toast at the end.

9. Conversations page

Open Conversations.
Every session with title (first question), persona, message count and last activity.
Open one.
Full transcript with citation chips and the last turn's latency/cost badges. "Continue by voice" reopens it in the agent with the same history.
Delete one.
A confirmation dialog, then it disappears.

10. API and Swagger checks

Open http://localhost:4000/api/docs. Useful calls:

curl -s localhost:4000/api/health
curl -s -X POST localhost:4000/api/knowledge/search -H 'content-type: application/json' \
  -d '{"query":"hotel budget per night in London","topK":3,"mode":"hybrid"}'
curl -s -X POST localhost:4000/api/agent/turn -H 'content-type: application/json' \
  -d '{"text":"How many PTO days do I have left this year?"}'
curl -s localhost:4000/api/tools
curl -s localhost:4000/api/tools/usage
curl -s localhost:4000/api/hr/tickets
curl -s localhost:4000/api/conversations

The agent-turn response contains the assistant message with sources, steps (the trace) and metrics (latency, tokens, cost), which is the easiest way to script checks.

12. Troubleshooting

SymptomCause and fix
Badge says "disconnected"The API is not running on port 4000. pnpm dev, or check http://localhost:4000/api/health.
Orb disabled / "Microphone access is not available"Browser blocked the microphone or the page is not on localhost/https. Allow it in site settings and reload.
Hands-free never triggersSpeak clearly for at least half a second; the detector ignores very short sounds. Check the input device in the browser's site settings.
The agent interrupts itselfSpeaker audio feeding back into the microphone. Use headphones or Push to talk.
Spoken replies are a chime, transcripts are demo phrasesMock mode: no key found. Add OPENAI_API_KEY to .env, restart the API, run pnpm db:seed to re-embed.
Answers cite nothing / "weak" grades everywhereIndex embedded with a different provider. Run pnpm db:seed (documents remember their embedding model).
Port already allocatedAnother Postgres uses 5434 or Redis 6379: change the host port in docker/docker-compose.yml and DATABASE_URL / REDIS_URL.
Reindex jobs stay queuedRedis is down or the API worker is not running. pnpm infra:up and restart the API.
